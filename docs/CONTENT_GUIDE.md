# نبض 3 — دليل المشروع والمحتوى

نبض موقع عربي ثابت لاكتشاف أخبار التقنية ومشاريع البرمجيات وأفكار البناء. يعمل دون خادم دائم. يفصل بين **الجمع الآلي من المصادر** و**الإثراء التحريري** الذي يضيفه النموذج المجدول أو محرر بشري. ليس كل خبر مترجمًا أو محللًا؛ توضح البطاقات الفرق بين وصف المصدر والشرح العربي الخاص والقوالب الاستكشافية.

## كيف يستفيد الزائر؟

- يبدأ بخمس إشارات متنوعة من أخبار آخر سبعة أيام. هذا انتقاء آلي بحسب المجالات والمؤشر التقديري وليس نشرة حررها إنسان.
- يفتح حالة المحتوى ليرى تاريخ الجمع وحالة كل مصدر والأخطاء الجزئية.
- يتوازن ترتيب الرئيسية التقديري بين خبرين ومشروع حتى لا تهيمن نجوم GitHub التراكمية؛ ترتيب الأحدث زمني. يستخدم الأقسام والبحث والتصفية حسب الفترة والمنطقة ولغة المشروع ووجود شرح خاص.
- يفتح التفاصيل ليجد الملخص والمصدر، وعند الإثراء يجد لماذا يهمه الخبر ولمن يفيد وخطوات البدء والقيود.
- يفتح مشروعًا ليقرأ شرح آلية عمله ومتطلباته ثم اقتراحات التطوير والمشاريع المستقلة والاستخدامات الدينية المناسبة.
- يحفظ خبرًا أو فكرة أو ينسخ رابط التفاصيل. الحفظ محلي لهذا المتصفح، وقد يتعذر فتح عنصر قديم خرج من التغذية. روابط التفاصيل تعمل ما دام العنصر أو مشروع الفكرة موجودًا؛ ليست أرشيفًا دائمًا.

## رحلة البيانات

1. يشغّل GitHub Actions المجمع كل ثلاث ساعات، أو يدويًا، أو بعد دفع إلى main.
2. يجلب `scripts/update_feed.py` خلاصات RSS/Atom من ناشرين عرب وعالميين ومصادر رسمية، وHacker News ونتائج بحث GitHub.
3. تعمل خلاصات RSS بالتوازي بحد أقصى خمسة طلبات. تعاد بعض الطلبات المؤقتة حتى ثلاث محاولات، مع مهلة وتراجع محدودين.
4. ينظّف النص والروابط، ويستبعد الأخبار بلا تاريخ صالح أو القديمة أكثر من 21 يومًا من دفعة RSS الجديدة. لا يعطي تاريخًا حديثًا لخبر مجهول التاريخ.
5. يدمج العناصر بالروابط وبصمة العنوان ويحفظ الصور والهوية السابقة. بصمة العنوان تقريبية وقد تدمج تغطيات لها العنوان نفسه؛ لا تفهم تشابه الأحداث دلاليًا.
6. يحتفظ افتراضيًا بما يصل إلى 700 خبر و100 مشروع، مع توزيع عبر التصنيفات والمجالات حتى لا تبتلع فئة واحدة بقية المحتوى. هذه حدود قصوى وليست وعدًا بعدد يومي. يظل المحتوى القديم في اللقطة ما دام ضمن حدود الاحتفاظ؛ فلاتر التاريخ تميزه.
7. يكتب `feed.json` و`seen.json` وحالة الجمع في `status.json`. عند فشل جميع المصادر يحافظ على التغذية وتاريخ آخر نجاح ويحدث تقرير الحالة فقط. الملفات تستبدل ذريًا كلٌ على حدة، ولا تُحفظ مفاتيح الوصول فيها.
8. تقرأ الواجهة التغذية وتضيف لها السجلات المطابقة بالمعرف والرابط من `editorial.json`. يبقى وصف المصدر الأصلي متاحًا للبحث.
9. يضيف `research.json` الدراسات الموجودة لثلاثة مشاريع. وتوفر `ideas.js` قوالب المجالات لبقية المشاريع مع وسمها بأنها استكشافية. تتجاوز قوائم editorial المخصصة القوالب لذلك المشروع؛ لا يُفرض عدد 10 إن لم يتوفر محتوى جيد.
10. ينشر GitHub Pages الملفات. يتحقق المتصفح كل 15 دقيقة من أحدث نسخة منشورة؛ زر التحديث لا يشغل عملية الجمع أو النموذج.

## تشغيل محلي

```bash
python -m http.server 8000 --directory site
```

افتح http://localhost:8000. يحتاج جمع محتوى جديد اتصالًا بالمصادر:

```bash
python scripts/update_feed.py
```

يمكن رفع حدود الاحتفاظ ضمن الحدود المسموح بها:

```bash
NABDH_MAX_NEWS=1000 NABDH_MAX_PROJECTS=150 python scripts/update_feed.py
```

زيادة الحدود تكبّر الملفات ووقت تحميلها. حد الأخبار المسموح 1–2000 والمشاريع 1–250. لا توجد خدمة نموذج لغوي داخل هذا السكربت. GITHUB_TOKEN اختياري محليًا لتحسين حدود GitHub API ويقدمه Actions أثناء التشغيل.

## الإثراء المجدول

```bash
python scripts/editorial.py queue /tmp/news-queue.json --kind news --limit 12
python scripts/editorial.py queue /tmp/project-queue.json --kind project --limit 2
python scripts/editorial.py validate /tmp/results.json
python scripts/editorial.py import /tmp/results.json
```

أداة queue لا تستدعي نموذجًا. تعطي العناصر غير المثرية أولًا مع بيانات المصدر. يحفظ import السجلات الأخرى ويتحقق من المعرف والرابط مقابل أحدث تغذية محلية. استورد النتائج على نسخة محدثة وراجع diff قبل إرسالها. تُستبدل بطاقة الإثراء للمعرف المرسل كاملة؛ احتفظ بحقولها القديمة إن لم تقصد حذفها. تحافظ المعرفات على الربط بين عمليات الجمع.

تتطلب كل بطاقة عنوانًا وملخصًا وأهمية ومصادر HTTPS وتاريخ مراجعة مع منطقة زمنية وأساس المراجعة. `metadata` يعني بيانات وصفية، و`article` قراءة المقال، و`readme` مراجعة التوثيق، و`code` فحص الشيفرة، و`tested` تجربة موثقة بحقل `testEvidence`. التحقق آلي للبنية ولا يثبت صدق الادعاء؛ تبقى مراجعة المصادر مسؤولية المحرر.

لقوائم المقترحات حتى عشرة عناصر لكل نوع. كل عنصر يحتاج `title, problem, approach, stack, steps, metric, difficulty, risks, sources`. الحقول `confidence` اختيارية. ضع تقدير الجهد في `difficulty` واذكر أنه تقدير. لا تغيّر ترتيب القوائم السابقة لأن بعض روابط الأفكار والمحفوظات تشير إلى مواضعها. لا تستبدل تحسينًا بفكرة أخرى تحت الموضع نفسه.

يوجد شرح ابتدائي لثلاثة مشاريع مبني على مراجعة README، لا تجربة التشغيل. معظم الأخبار تنتظر الإثراء من المهمة المجدولة. فتح واجهة الموقع لا يُنشئ ملخصًا جديدًا.

يفتح الاختبار خادمًا مؤقتًا بنفسه ويتحقق من التصفح والتصفية والحفظ وروابط التفاصيل وعرض الهاتف ومعالجة فشل التحديث ومحتوى الإثراء. لا يحتاج خدمات خارجية للصور والخطوط، ويوقف طلباتها لتثبيت الاختبار.

## إضافة مصدر أو مجال

أضف رباعية الاسم والرابط والتصنيف والمنطقة إلى FEEDS، ثم اختبر الخلاصة الفعلية وتواريخها وروابطها. تظهر حالة نجاحها أو فشلها في status.json. أضف مجال GitHub مناسبًا إلى REPO_QUERIES وتحقق من حدود الطلبات. أي قسم واجهة جديد يحتاج ربط تصنيفه بالتنقل والمرشحات؛ لا تكفي إضافة اسم مصدر.

## النشر والحدود

اختر GitHub Actions كمصدر GitHub Pages، ثم شغّل workflow الموجود. النشر يحتاج صلاحيات Pages وكتابة محتوى المستودع. يتحقق workflow من Python وبنية الإثراء وصياغة JavaScript قبل الجمع. يوجد أيضًا workflow فحص لطلبات الدمج دون صلاحية نشر أو كتابة.

لا يتضمن الموقع أرشيفًا دائمًا أو مزامنة حسابات أو بثًا لحظيًا أو بحثًا كامل النص في المقالات. ليس كل مصدر يوفر صورة أو وصفًا كافيًا. عند تعذر الصورة يظهر بديل موضح. صور الحساب ليست صورًا للمشروع. النجوم تراكمية وليست زيادة اليوم؛ المؤشر ليس قياس مشاهدات أو حكمًا على الجودة. قد تتأخر الجداول أو تتعطل المصادر. الجمع العام لا يحتاج API مدفوعًا، لكن النموذج المجدول وتشغيل المشاريع التي يشرحها قد يترتب عليهما تكلفة مستقلة.
