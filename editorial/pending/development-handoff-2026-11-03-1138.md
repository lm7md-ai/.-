# متطلبات عرض المحتوى لمساعد التطوير — دون تنفيذ تطوير

1. لا تعدّل الشيفرة أو التصميم أو workflows أو إعدادات Pages ضمن هذه المراجعة.
2. بطاقة الخبر المثرى يجب أن تعرض: titleAr وsummaryAr وwhyItMatters وaudience وnextSteps وlimitations وreviewedAt وbasis وsources.
3. أظهر شارة واضحة لقيمة basis: article / metadata / readme / code / tested. عند metadata يجب توضيح أن النص مبني على وصف أو مقتطف لا على قراءة المقال الكامل.
4. اعرض المصادر كرابط منفصل بعنوان المصدر، ولا تستبدل الرابط الأصلي في سجل feed بهوية مولدة من العنوان.
5. أظهر nextSteps كقائمة قصيرة، وlimitations في موضع ظاهر لا يدفن ادعاءات المصدر أو القيود.
6. للأحداث السعودية، اعرض حالة الحدث وتاريخه؛ لا تصف حدثًا ماضيًا بأنه فرصة تسجيل مفتوحة.
7. المشاريع: ميّز بين published_existing_card وresearch_only_not_in_feed وarchived، ولا تعرض ملفات المكتبة البحثية كأنها بطاقات منشورة.
8. لا تعرض testEvidence أو شارة اختبار ما لم توجد تجربة فعلية موثقة؛ في مراجعة المشاريع السابقة testEvidence=0.
9. تغطية المشاريع الحالية 99/100؛ العنصر المتبقي يحتاج مراجعة مستقلة قبل إثرائه، ولا يُستكمل بحشو.
