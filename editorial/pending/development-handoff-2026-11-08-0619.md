# متطلبات عرض نَبض — تسليم لمساعد التطوير
تاريخ المراجعة: 2026-11-08 06:19 (+03)

هذا ملف متطلبات عرض فقط؛ لم يُنفّذ أي تطوير في هذه الدورة.

## تفاصيل الأخبار
- اربط التفاصيل بالمعرف الأصلي من feed، ولا تولّد ID من العنوان أو تغيّر URL.
- اعرض الحقول الموجودة في editorial كما هي: titleAr، summaryAr، whyItMatters، audience، nextSteps، limitations، reviewedAt، basis، sources.
- اعرض basis بوضوح كشارة مفهومة: article / metadata / readme / code / tested. لا تعرض metadata كأنه قراءة كاملة للمقال.
- اجعل كل مصدر قابلًا للفتح، وأظهر تاريخ المراجعة والمنطقة الزمنية.
- لا تخفِ القيود أو تنسب ادعاء الناشر إلى حقيقة مستقلة.

## تفاصيل المشاريع
- اعرض overview وrequirements وquickStart.
- اعرض improvements وspinoffs وreligious فقط إذا كانت القوائم موجودة وبها عناصر؛ لا تنشئ أقسامًا أو اقتراحات حشو.
- احتفظ بترتيب الأفكار الحالي وروابط المصادر. الإضافات الجديدة تلحق بنهاية القائمة ولا تستبدل أفكارًا سابقة.
- اعرض difficulty كتقدير، ولا تعرض testEvidence إلا إذا كان هناك دليل اختبار فعلي.
- لا تحوّل عناصر research-only إلى بطاقات عامة ما لم يوجد تطابق حرفي مع ID وURL ونوع project في feed.

## الروابط العميقة
- يدعم التطبيق الحالي المسار #item=<id>؛ حافظ على الروابط المبنية على ID الأصلي.
- يجب أن يبقى عنوان الخبر أو المشروع ورابط المصدر الأصلي قابلين للرجوع.

## نطاق هذه الدورة
- لا تغيّر JavaScript أو CSS أو HTML أو workflows أو إعدادات Pages أو الجدولة.
- لا تعدّل feed.json أو seen.json أو status.json.
- هذا التسليم مواصفات لمساعد التطوير فقط؛ لا تنفّذ تغييرات واجهة ضمن هذه الدورة.
